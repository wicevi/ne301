## ⚠️ Upgrade Notes

> 📖 **Upgrading from a version below v4.3.1** (v2.x, v4.3.0, ...):
> read the **[OTA Update Guide](../v4.3.1/NE301_v4.3.1_OTA_Update_Guide.md)** first and follow it in order.
>
> **Upgrading from v4.3.1**: the partition table is unchanged — upgrade the APP, Web and WiFi firmware one by one from the web Firmware Upgrade page. FSBL, model and co-processor firmware need no upgrade.

1. **Upgrade the WiFi firmware to `2.17.5.42`** and the Web to `1.5.1.0`. After the APP upgrade the device reports a WiFi firmware version mismatch; complete the WiFi firmware upgrade as prompted.
2. **USB function is off by default**: enable it under System Settings → Device Configuration when needed.
3. **PIR "Disable during preview" now defaults to "No"** (was "Yes"). This applies to new devices and after a factory reset only; upgraded devices keep their stored setting.
4. **The "Grayscale mode" switch is removed**: on IR boards, day/night mode handles the color / black-and-white switching.
5. **Motion-blur suppression** increases noise and image size in dark scenes; enable it according to the scene.

## ✨ New Features (Detail)

### 🔦 IR light board

- The device detects an IR light board from the factory hardware version
- **Day/night mode** (Image Management page):
  - Always day (color) / Always night (IR night vision): fixed
  - Scheduled window: night mode inside the window, day mode outside
  - Auto by ambient light: judged from the ambient-light sensor in real time; by default brightness ≤ 20% enters night and ≥ 80% returns to day, and the range in between keeps the current mode to avoid frequent switching
- **IR light** (Light Management page): adjustable intensity, plus subject-distance presets for 4 m / 5.5 m / 6.5 m / 9 m — lower intensity for near subjects to avoid over-exposure
- A dedicated tuning for the IR night-vision image (exposure, contrast, etc.)
- Sleep-wake captures decide the IR-cut filter and IR light from the saved day/night mode, without slowing the wake-up

### 🖼️ Image Optimization

- **Motion-blur suppression** (Image Management page, below Vertical Flip)
  - Caps the auto-exposure time at 10 ms. Measured: a person walking normally at 3 m shows about 12 px of smear instead of about 40 px
  - Dark scenes compensate with gain, so noise increases
  - Applies immediately and persists after reboot
- **Wake-capture exposure**
  - Replaces the fixed frame-skip wait with a luminance-based exposure-readiness check
  - In stable lighting the camera is ready to capture about 200 ms after it starts (this figure covers only the exposure convergence after camera start, not the system wake-up time)
  - Waits longer automatically when the scene changes, reducing under- or over-exposed captures
- **White balance & color tuning**
  - 3-point auto white balance enabled (incandescent / fluorescent / daylight) with the daylight point re-calibrated from field shots for more accurate day colors
  - Indoor and outdoor modes now share one image style and differ only in metering region

### 📷 Capture & Video

- **Stream parameters** (Device Tool page)
  - Resolution: sub-stream (AI input size) / main stream (720P) / main stream (1080P)
  - Bitrate and keyframe interval
  - Applied immediately after saving; the preview recovers by itself after a brief interruption
- **Runtime capture parameters** (Device Tool page)
  - Resolution (1080P / 720P / 4MP, linked to the stream), skip frames, JPEG quality
  - Apply to captures taken while the device is running only; sleep-wake captures are unaffected
- **AI capture filtering** (Capture Settings → Inference Config)
  - Enable/disable filtering, confidence threshold and the allowed result labels
  - Captures that do not match are neither stored nor uploaded
- **Batch download**: multi-select batch download in the Storage Management file browser and on the capture records page
- **Retention options**: the retention of uploaded files changes from an hours field to a preset list (none / 12 h / 1 d / … / 3 y / forever / custom)
- In standby or low-power mode, the Device Tool page offers a "Sleep-wake capture parameters" shortcut that jumps to the matching section of Capture Settings

### 🎯 Trigger

- **Device type**: PIR (PIR sensor module, with adjustable sensitivity and anti-jamming) / IO (plain level signal, edge selection only)
- **Anti-jamming**: triggers only after enough valid pulses are detected within a set time, reducing false triggers from sporadic interference
- **Quick presets**: Indoor standard / Outdoor anti-interference / Fast capture / Power saving — one click fills in the configuration
- **Sensitivity**: now a 1–100 scale (higher is more sensitive) with a sensitivity tier and a theoretical detection distance; existing configurations remain compatible

### 📶 Network & Time

- **WiFi upgrade**: host driver to WiseConnect 4.2.0 with firmware `2.17.5.42`
- **Auto reconnect**: after an unexpected link loss (WiFi drop, router reboot, PoE cable pull, cellular drop) the device reconnects by itself until the link is back; networks turned off manually stay off
- **WiFi fault recovery**: the hotspot and the client interface now recover independently, so a fault on one side no longer affects the other
- **USB function** (System Settings → Device Configuration)
  - Switch: when off, USB is not initialized at all to save power; off by default
  - IP mode: follow hotspot (default, shares 192.168.10.10) / custom
- **NTP time sync** (Device Configuration page): switch plus server list (up to 4, domain names or IPv4)
- **RTSP over TCP**: clients may choose TCP transport; video rides the same connection as RTSP
- The "Device Password" tab is renamed "Device Configuration" and groups password, NTP and USB

### 🤖 AI & Data Reporting

- Uploading a model on the Device Tool page now applies reliably: a model with a different input size is adapted automatically; a failed load rolls back to the previous state and reports the reason
- Object-detection labels now include the confidence
- AI-result telemetry can be reported in batches to cut the message count (set through the config file or the API)
- Sub-cell refinement for body keypoints stops the points from jumping (optional, enabled by a model parameter)

## 🐛 Fixes

The following issues existed in v4.3.1 and are fixed in v4.3.2.

### AI & Model

| Issue | After |
|-------|-------|
| With a YuNet face-detection model the device misbehaved (rebooted or froze) and could not detect | Detection works |
| After a model change the label text on detection boxes could render as colored speckle noise | Fixed |

### Capture & Upload

| Issue | After |
|-------|-------|
| Captures taken before the clock was ever synced were neither uploaded nor cleaned up | Filed under 1970-01-01, uploaded normally and cleaned up first |
| In instant-upload mode one capture could be uploaded twice, and an already-uploaded record could be marked as failed | Fixed |

### Network

| Issue | After |
|-------|-------|
| Several sporadic faults | Fixed for better system stability |
| Reading the WiFi firmware version stalled for ~30 s when the WiFi chip was unresponsive, without triggering recovery | About 3 s, and WiFi recovery is triggered automatically |
| The hotspot and the client interface interfered with each other during WiFi fault recovery | Each recovers independently |
| On a weak cellular signal, PIN and operator commands timed out, were misreported as failed and re-sent | Timeouts widened based on field measurements |

### Button, System & Preview

| Issue | After |
|-------|-------|
| On a poor network the physical capture button stopped responding and repeated presses had no effect | The capture runs in the background and the button responds at once |
| Concurrent log writes from several tasks could, in rare cases, cause a system fault | Fixed |
| The web preview stuttered periodically when the video frame rate was low | Fixed |

## 🔌 Web API Changes (for platform integration)

Endpoint count 176 → 187, added:

| Method | Path | Purpose |
|--------|------|---------|
| `GET` / `POST` | `/api/v1/device/stream/config` | Stream parameters |
| `GET` | `/api/v1/device/usb` | USB running state |
| `POST` | `/api/v1/device/usb/config` | USB switch and IP mode |
| `GET` / `POST` | `/api/v1/device/day-night/config` | Day/night mode configuration |
| `GET` | `/api/v1/device/day-night/status` | Day/night mode status |
| `GET` / `POST` | `/api/v1/system/ntp/config` | NTP configuration |
| `POST` | `/api/v1/work-mode/timer-trigger` | Partial update of timer-trigger parameters |
| `POST` | `/api/v1/work-mode/remote-trigger` | Partial update of remote-trigger parameters |

Behavior change on an existing endpoint:

- MQTT config (`/api/v1/apps/mqtt/config`): certificate data sent without a file path is now stored on the device and kept after reboot (previously it was held in memory only)

Full request, response and error details are in the [NE301 v4.3.2 HTTP API Reference](./NE301_v4.3.2_HTTP_API.md).
